PHASE 1 · WEEKS 1–3Trust — make every promise in the UI real

Everything here is a feature the UI already advertises but doesn't deliver. Ship these before adding anything new.

1.1 Real PDF / PNG export 4–5 days

Approach: headless-browser rendering in export_service (Python) using playwright — render the existing public report page for a short-lived internal token, then page.pdf() / page.screenshot(). Reuse the existing async job flow (ExportJob + POST /export/trigger + polling + download) — only the worker body changes from stub to real.

  • Add playwright + chromium to export_service (Dockerfile: playwright install --with-deps chromium)
  • Mint an internal single-use share token for the render (revoke after)
  • Add the missing POST /analyst/canvas/{token}/export/pdf endpoint the share page already calls; return job id, let the page poll
  • Per-widget PNG in the builder can keep client-side html2canvas (already works)
  • Agentic hook: agent adds a cover page — title, date, executive summary from the existing ai-summary endpoint
backend/export_service/routers/pdf_export.py · png_export.py · backend/agent_service/routers/analyst.py · routers/exports.py · frontend app/share/canvas/[token]/page.tsx
"Export PDF" on a shared canvas downloads a real multi-page PDF with all charts rendered; export job status reflects reality.

1.2 Email sender for snapshot schedules 2–3 days needs 1.1 for images

Approach: new shared/email.py — Resend HTTP API by default (one env var), SMTP fallback. A per-minute APScheduler tick scans SnapshotSchedule.next_send_at <= now, renders the PNG (1.1), asks the agent for a "what changed since last send" digest, sends, advances next_send_at.

  • Env: RESEND_API_KEY or SMTP_HOST/PORT/USER/PASS; no-op with a loud log when unconfigured
  • Ship v1 as HTML email (headline numbers + AI digest + link); attach PNG once 1.1 lands
  • Record send history on the schedule row (last_sent_at, last_error) and surface it in ScheduleModal
backend/shared/email.py (new) · agent_service/scheduler.py · routers/analyst.py · frontend ScheduleModal (share page)
A schedule created on a share page actually delivers an email at the right time, with an agent-written summary of what changed.

1.3 Persist report-view state + server-side bookmarks/annotations 3–4 days

Approach: a report_prefs object inside Dashboard.layout_config (PATCH endpoint already exists): theme, layout mode, bg pattern, KPI density, per-widget chart-type overrides, AI table names. VisuallReport reads it on mount and writes debounced. Bookmarks/annotations move from localStorage to the existing DashboardBookmark/DashboardAnnotation tables via new owner-scoped endpoints (the analyst-token endpoints already exist — add authenticated dashboard-scoped twins).

frontend components/canvas/VisuallReport.tsx · backend agent_service/main.py (bookmark/annotation endpoints) · shared/models/bookmarks.py · annotations.py (add user FK)
Reload the report view — theme, layout, overrides, bookmarks, annotations all restore; a collaborator sees the same bookmarks.

1.4 Full undo/redo command stack 4–6 days

Approach: replace the layout-snapshot stacks with a command pattern: useCommandStack hook where every mutation is {label, do(), undo()}. Commands: move/resize (batch per gesture), rename, chart-type change, palette, add/delete widget (delete stores the full widget payload for restore via canvasApi.addWidget), page add/rename/delete/reorder. Every AI copilot insertion pushes a command too — "undo what the AI did" becomes Ctrl+Z, which is the core trust story of the product.

  • Keep the 4-second delete banner as UX sugar on top of the stack
  • Show the command label in the toast ("Undid: delete 'Revenue by Region'")
frontend app/(app)/projects/[id]/canvas/[canvasId]/page.tsx · new hooks/useCommandStack.ts · components/canvas/CanvasChatPanel.tsx
Any 10 consecutive mixed actions (edits, deletes, AI inserts, page ops) can be walked back with Ctrl+Z and forward with Ctrl+Y.

PHASE 2 · WEEKS 4–7BI parity + editor experience

The authoring depth that makes it feel like a real BI tool — built so every control is also reachable by the agent.

2.1 Widget selection + contextual property panel 5–8 days

Approach: introduce a selection model (click card → selected, Esc/click-canvas → deselect) with a 2px brand outline. A right-side panel (like the chat panel, 300px) with three tabs:

  • Format — title, palette, number format, conditional rules (2.3), axis labels — migrated out of the widget header
  • Data — table used, SQL (read + "edit with AI"), refresh, row limit
  • AI — the originating question (store it in config.question when the chat adds a widget), the agent's reasoning, one-click variants ("as line", "monthly", "top 10 only")

Header keeps only: drag grip, title, lock, delete. Everything else moves to the panel. This is the single largest UX upgrade after the page redesign.

frontend new components/canvas/PropertyPanel.tsx · CanvasWidget.tsx (slim header) · canvas page.tsx (selection state) · CanvasChatPanel.tsx (store config.question)
Selecting any widget shows its full story — what was asked, what SQL ran, why — and every format change previews live.

2.2 Text / image / button widgets 3–4 days

Approach: new widget_type values (text, image, button) with content in config (markdown string / image data-URI or URL / action spec). Renderer branch before ChartRenderer. Insert via a toolbar "Insert" menu and a chat tool so "add a title saying Q3 Review" works. Buttons fire agent actions ("refresh & summarize this page") — the first taste of agent-native interactivity.

frontend components/canvas/StaticWidgets.tsx (new) · CanvasWidget.tsx · canvas page.tsx (Insert menu) · backend: none (config JSONB already fits)
A page can carry a styled headline, a logo, and a "Refresh & Summarize" button created either manually or by asking the copilot.

2.3 Number formats + conditional formatting 4–5 days

Approach: config.format ({kind: number|currency|percent, decimals, prefix, compact}) honored by a single shared formatter in ChartRenderer (replacing heuristic fmtNum when set), and config.rules ([{when: "value < 20", color, bold}]) applied to table cells, KPI values, and bar colors. Add an agent tool set_widget_format so "show margin in red when below 20%" writes a rule — visible and editable in the Format tab.

frontend components/charts/ChartRenderer.tsx · PropertyPanel.tsx · backend agent_service chat tool registry (tools/)
The same rule can be created by hand in the panel or by one sentence in chat, and both show identically in the Format tab.

2.4 Multi-select, align/distribute, "Tidy up" 4 days

Approach: shift-click + marquee selection over the grid; alignment toolbar (align left/right/top, distribute, match size) that computes new layout items and pushes ONE command (1.4). "Tidy up" button + chat command runs the existing autoArrange logic scoped to the selection.

frontend canvas page.tsx · new components/canvas/SelectionToolbar.tsx
Select 4 KPIs → "align top + equal width" in one click or one sentence; Ctrl+Z restores.

2.5 Cross-filtering in the editor 4–5 days

Approach: port VisuallReport's onDataPointClick → POST /dashboards/{id}/requery flow into the editor grid, with an "edit interactions" mode: select a source widget → toggle per-target respond/ignore, stored as config.interactions. Active cross-filter shows the existing banner + chip.

frontend canvas page.tsx · CanvasWidget.tsx · ChartRenderer.tsx (already has click handlers) · backend /requery (exists)
Clicking a bar in the editor filters the other widgets, respecting the interaction matrix, with a visible clear affordance.

2.6 Remaining visual polish 4 days total

  • Editor theming — apply the 8 report themes in the editor; persist to the existing Dashboard.theme column (currently unused, defaults "frost")
  • Alignment guides — overlay lines during drag computed from neighboring layout edges (custom overlay; react-grid-layout untouched)
  • Page tabs — icons/colors per page, overflow scroll, template "+" menu
  • In-canvas generation skeleton — while the copilot generates, drop a shimmering placeholder card at the next free grid slot; replace on arrival
frontend canvas page.tsx · CanvasPageTabs.tsx · CanvasChatPanel.tsx · backend PATCH /dashboards/{id} (theme — exists)
Edit mode and report mode share one visual language; generating a chart visibly happens ON the canvas.

PHASE 3 · WEEKS 8–13Agentic differentiators — what Power BI can't copy

Each of these turns an existing backend capability into a product-defining agent experience.

3.1 Metric registry UI + verified metrics 3 days

Approach: the backend already exists (metric_registry.py + CRUD endpoints, shipped in Phase 0). Build the "Metrics" settings page: metric cards (definition, table, expression, date column, synonyms), a verified badge, and agent proposals — mine query memory for frequently asked metric terms and suggest "pin this definition?" Registered metrics make the deterministic SQL templates fire (already wired).

frontend new app/(app)/projects/[id]/metrics/page.tsx · lib/api.ts · backend endpoints (exist) · query_memory.py (term frequency helper)
Defining "placements" once makes every placement question answer identically, instantly, with a "verified metric" badge on the widget.

3.2 Agent alerts with explanations 6–8 days

Approach: AlertRule table (widget_id, plain-language condition, parsed rule JSON, cadence, channel, is_active). Bell icon on KPI/chart widgets → composer where the user types the condition ("tell me if daily applications drop below 5") — the agent parses it to a rule. Scheduler tick evaluates: run widget SQL, apply threshold or 2σ anomaly detection, and on trigger have the agent write a one-paragraph explanation (what happened, vs baseline, likely dimension driving it) → in-app notification + email (1.2).

backend new shared/models/alerts.py + agent_service/routers/alerts.py · scheduler.py · frontend PropertyPanel/CanvasWidget bell + AlertComposer.tsx
"Watch this chart and tell me when something unusual happens" produces a working alert whose notifications explain, not just notify.

3.3 "Explain this point" everywhere 4–5 days

Approach: right-click any data point → "Why?" → POST /dashboards/{id}/explain-point with {widget, column, value}. The agent runs decomposition queries (same metric grouped by each other candidate dimension, plus prior-period comparison — deterministic SQL, LLM only for the narrative) and returns a ranked "what drove this" answer in an inline popover with the supporting mini-charts.

backend new routers/explain.py (reuses graph_rag + query executor) · frontend ChartRenderer.tsx (context menu) · ExplainPopover.tsx (new)
Right-click the June spike → within seconds: "June's jump is 80% driven by the VCS channel; the other channels were flat."

3.4 Version history + prose diff 4 days

Approach: wire the existing dead DashboardVersion table: snapshot {widgets, layout, pages, theme} on meaningful saves (debounced, max 1/10min, keep 50). History drawer with timeline; restore = one command (1.4). The agent renders diffs in prose ("2 widgets added, revenue KPI switched from SUM to AVG") by comparing snapshot JSON.

backend agent_service/main.py (snapshot on layout/widget writes, history + restore endpoints) · shared/models/phase2.py (exists) · frontend HistoryDrawer.tsx (new)
Any canvas can be restored to any of its last 50 states, and the timeline reads like a changelog, not JSON.

3.5 Agent-generated page layouts 5–6 days

Approach: "Generate page" flow (empty-state templates + page "+" menu): user states a goal → orchestrator plans 6–8 widget specs (reusing the dashboard pipeline) → renders 2–3 candidate arrangements as lightweight thumbnails (client-side, from chart_data) → user picks one → widgets + layout committed as one undoable command.

backend orchestrator.run_dashboard_pipeline (exists — add layout-candidates step) · frontend PageTemplateModal.tsx (new) · canvas page.tsx
"Make an executive overview page for placements" yields a picked-from-candidates page in under a minute, fully undoable.

3.6 Data-model surfaces: relationship editor + drill hierarchies + cascading slicers 8–10 days

  • Relationship editor — render the FK graph from schema_cache.relationship_graph as an interactive diagram; confirm/override/annotate edges; confirmed edges get a retrieval score boost and become preferred JOIN paths
  • Drill hierarchies — agent infers (date and categorical) hierarchies once per connection, stores them beside the metric registry; DrillDownModal uses them deterministically, LLM only as fallback
  • Cascading slicers — slicer-values endpoint accepts the other active slicer filters; empty-result combinations trigger an agent suggestion of the closest non-empty state
backend schema_cache.py · graph_rag_retriever.py · routers/analyst.py (slicer-values) · tier5.py (drilldown) · frontend ModelView.tsx (new) · SlicerWidget.tsx · DrillDownModal.tsx
Drill-down is instant on defined paths; slicers never strand the user on an empty page; confirmed joins measurably improve the golden-question eval.

GOVERNANCESequencing, risks & working agreements

Why this order

RuleRationale
Trust before features (Phase 1 first)Every advertised-but-broken button actively costs credibility with each demo. Fix reality before adding surface.
Command stack (1.4) before the property panel (2.1)Every new mutation surface should be born undoable — retrofitting undo is 3× the work.
Property panel (2.1) before formatting (2.3) and alerts (3.2)They need a home; the panel is that home.
Email (1.2) before alerts (3.2)Alerts need a delivery channel that works.
Metric registry UI (3.1) early in Phase 3Backend is already live; smallest effort-to-differentiation ratio in the whole plan.

Key risks

RiskMitigation
Playwright/chromium in export_service bloats the image and needs system depsIsolate export_service in its own container (already separate); pin chromium; keep html2canvas as client-side fallback.
Command-stack refactor destabilizes the editorMigrate one mutation type at a time behind the same hook; layout commands first (they already have snapshots).
Free-text RLS clauses + LLM drilldown SQL remain injection-adjacentPhase 2 hardening: run all injected clauses through basic_sql_lint, and validate drilldown SQL with the same pre-execution checks as the main pipeline.
react-grid-layout limits (no overlap, no free positioning)Accept for now — the 1280px document sheet already delivers the "real BI page" feel. Re-evaluate a custom drag layer only after Phase 2.

Working agreements (apply to every item)

AgreementMeaning
Agent-parity ruleAny new control added to the UI ships with a matching agent tool in the same PR — nothing is manual-only.
Undoable-by-defaultEvery mutation goes through the command stack, including agent actions.
Show-your-workAnything the agent creates records its originating question + SQL + reasoning in config, surfaced in the AI tab.
Eval-gatedRetrieval/prompt changes must keep the golden-question harness green (backend/scripts/eval_golden_questions.py); add a golden question with every retrieval bug fixed.
