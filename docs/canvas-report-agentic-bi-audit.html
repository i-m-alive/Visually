00 Executive summary

Both apps share one backend (/dashboards/*) and the same entity model — a "dashboard", "canvas", and "report" are the same object. The web app is the mature reference implementation; mobile reached broad parity in the last build but still trails in three areas: direct-manipulation editing, auto-insight surfacing, and export breadth. Neither platform yet has the three things that separate a "dashboard tool" from an "agentic BI platform": real-time collaboration, a template gallery, and data lineage / audit governance.

Full — wired end-to-end Partial — stubbed, backend-only, or dead code Missing — not present

The three headline takeaways

  • Mobile's biggest single gap is editing ergonomics. The web app uses react-grid-layout for true drag/drop/resize with undo/redo; mobile is a vertical stack with a resize stepper and move-up/down. This is the most visible "it feels unfinished" gap.
  • Mobile has the agentic backend but under-surfaces it. Multi-agent build, explain, health, and self-healing all work — but auto-insight discovery, root-cause, guardrails, and cross-filtering that the web app exposes are not wired into the mobile editor.
  • Several features are "done" in code but invisible. Mobile annotations (full backend + client API) and what-if (a real function) have no UI; the image widget stores a URI but never renders it; calculated measures are stored on both platforms but never injected into rendering. These are cheap, high-credibility wins.

07 Bugs & correctness issues

Concrete defects (not just missing features) found during the audit — these erode trust and should be fixed first.

Image widget never renders the image mobile~1 hr

+Image stores config.image_uri, but ChartRenderer only shows a text hint 🖼 {uri}. Users think image widgets are broken.

Fix: render <Image source={{uri}} resizeMode="contain"/> in the image case; add an expo-image-picker/library-picker to set the URI.

Calculated measures are stored but never applied at render web + mobile~1 day

Both platforms let you define/AI-generate measures, but they are a passive catalog — no widget SQL resolves a measure reference. The feature looks complete but does nothing to charts.

Fix: at query-build time, expand {{measure.name}} references into their stored SQL expression (server-side, in the requery/widget path), and expose measures as pickable fields in the chart editor.

Dead code: annotations & what-if have no UI mobile~0.5 day each

Full annotation backend CRUD + client API (listAnnotations/addAnnotation/…) and a working applyWhatIf() function exist but are called by no screen. Ships as unused weight and a false sense of completeness.

Fix: either wire the UI (annotation layer + list modal; a what-if verb in WidgetActionSheet) or remove the dead code. Wiring is the better ROI — the hard part (backend) is done.

Advanced charts silently fall back without telling the user web~2 hr

sankey/sunburst/network/chord/gantt render as a donut or sorted bar. The user asked for a sankey and silently got a pie — a correctness/trust bug, not just a fidelity gap.

Fix: show an explicit "This chart type isn't supported yet — showing data as a table" badge, or implement the real renderer. Never silently substitute a semantically different chart.

No UI to define a new slicer/filter in the mobile editor mobile~0.5 day

SlicerBar can only apply filters that already exist in filter_config; there's no in-editor way to create one. setFilterConfig exists in the client but is unsurfaced.

Fix: add a "+ Filter" affordance that picks a column (from schema-context) + slicer type and writes filter_config.

Drill-down & explain auto-pick the first data point mobile~0.5 day

Because there's no interactive point selection, "drill" / "explain" always operate on the first row/column rather than what the user tapped.

Fix: capture the tapped datum from the tooltip event and pass its dimension/value into the drilldown/explain payload.

Pivot table is a flat table web + mobile~1–2 days

pivot_table renders every row/column flat with no row/col grouping or subtotals — not a pivot.

Fix: implement a real pivot (group-by rows × columns, aggregate cells, subtotal/total rows). Shared logic can live in the backend so both clients render the same matrix.

08 Prioritized remediation plan

Ordered by value ÷ effort. P0 = correctness/credibility. P1 = close the mobile↔web gap. P2 = reach the agentic-BI frontier. As of 2026-07-20, every mobile P0/P1 item and the mobile P2-1/P2-4/P2-6 items below are shipped (see the update banner at the top); remaining P2 items (real-time collaboration, PPTX, advanced chart renderers, data lineage) stay deferred.

P0 — Correctness & "free" wins (days, not weeks)

P0-1 Render the image widget + picker mobile

Files: src/components/ChartRenderer.tsx (image case), WidgetEditModal.tsx (URI picker).

P0-2 Wire annotations UI over the existing backend mobile

Files: new AnnotationsModal.tsx + overlay in CanvasEditorScreen.tsx; API already in src/canvas/api.ts.

P0-3 Actually apply calculated measures at render web + mobile

Files: backend widget/requery SQL builder (measure expansion) + tier5.py measures resolve; chart-editor field picker on both clients.

P0-4 Honest "unsupported chart" state instead of silent fallback web

Files: frontend/components/charts/ChartRenderer.tsx fallback branches.

P0-5 Per-widget CSV export from cached rows mobile

Files: WidgetActionSheet.tsx + a CSV util; reuse the existing Share path.

P1 — Close the mobile ↔ web gap

P1-1 Gesture drag & resize on the 12-col grid mobile

The headline mobile gap. Files: CanvasEditorScreen.tsx with react-native-gesture-handler + reanimated; snap to the existing position_x/y/width/height model and persist via updateLayout. Add an in-memory undo/redo stack while here.

P1-2 Cross-filtering mobile

Files: tooltip datum handler in ChartRenderer.tsx → transient slicer override → requery siblings in CanvasEditorScreen.tsx. Web logic in VisuallReport.tsx is the reference.

P1-3 Surface auto-insights + insight discovery mobile

Files: call existing /ai-summary, /ai-insight, /intelligence-discovery from a new "Insights" / "Suggest widgets" action; render in AnalysisModal.

P1-4 Server export (PDF/HTML) + .vly import mobile

Files: src/canvas/api.ts (export trigger + job poll), a share action in the toolbar. Backend export_service already supports html/pdf/png.

P1-5 Filter builder + interactive drill/explain point selection mobile

Files: SlicerBar.tsx ("+ Filter"), tapped-datum plumbing into drilldown/explain payloads.

P1-6 Port the guardrail/validator into the mobile build path mobile backend

Files: canvas_builder.py writers → run generated SQL through the shared validator_agent before persisting; port root_cause_agent as a "Why did this change?" action.

P2 — Reach the agentic-BI frontier (both platforms)

P2-1 Template gallery + "save as template"

New starter canvases (finance/sales/ops) seeded from the multi-agent builder; a /dashboards/templates route + a gallery on the "New canvas" flow.

P2-2 Real-time collaboration (presence + co-edit)

Biggest platform investment. Add a CRDT/OT layer (yjs) over layout_config with a WebSocket presence channel; the AI-job ws_manager is a starting point for the socket infra.

P2-3 Data lineage & audit trail

Record which tables/columns fed each widget (the schema-scope + generated SQL already expose this) and a per-dashboard access/query log. Surface a "Lineage" tab in settings.

P2-4 True scenario / what-if planning

Driver-based model beyond KPI sliders: pick input measures, apply % / absolute deltas, recompute dependent widgets. Unify the web sliders and the mobile applyWhatIf() into one engine.

P2-5 PPTX export & scheduled exec digests everywhere

Add a pptx generator to export_service; expose snapshot-email scheduling in the mobile canvas settings.

P2-6 Advanced chart renderers + true pivot

Implement sankey/sunburst/network natively (or a shared spec both clients honor); build a real pivot engine server-side.

Audit scope limited to canvas / report / dashboard creation. Every "Full / Partial / Missing" mark was verified against source in both repos (Visually web and VisuallyMobile).
