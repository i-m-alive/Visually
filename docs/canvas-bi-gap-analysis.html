1What the platform already has

Roughly Power BI's surface area at 30–40% depth. This is a serious foundation:

  • 42 chart types (bar/line/pie through sankey, chord, gantt, choropleth, org chart, word cloud) rendered via recharts + custom SVG
  • Multi-page canvases — add, rename, delete, duplicate, drag-reorder (bottom tab strip, Power BI convention)
  • Drag/resize grid editor (react-grid-layout, 12 columns, 70px rows) with auto-arrange by widget type
  • AI copilot in the canvas — chat generates widgets, streams responses, adds to the active page
  • Cross-filtering + AI drill-down (report view) — click a bar/slice → server-side requery of all widgets
  • Slicers — dropdown / checkbox / date-range, token-scoped on public pages
  • Calculated measures with an AI generator (description → SQL expression)
  • Row-Level Security policies (per-user WHERE clauses)
  • Sharing — live/snapshot tokens with expiry, collaborators (viewer/editor), embed iframes, three public skins (share / embed / executive report)
  • .vly / .ovly export-import — portable canvas bundles, offline mode with DuckDB + Parquet
  • Scheduled refresh (cron presets via APScheduler) + per-widget manual refresh
  • 8 report themes incl. glassmorphism, dark, accessible; 4 background patterns; slide/story mode; focus mode; newspaper layout
  • Client-side analytics — linear forecast, prior-period comparison, 2σ anomaly highlighting, auto-captions, key-driver callouts
  • Annotations & bookmarks (share view), SQL sandbox, schema browser, email-snapshot schedule UI

2Broken or half-built features — fix before adding anything

Found during the code audit. These matter more than new features because users will hit them and lose trust.

PDF / PNG export is a stub. export_service returns not_implemented, render_service returns empty images, and the share page's "Export PDF" button calls an endpoint that does not exist — the "PDF export queued…" alert is misleading. Only per-widget CSV works. export_service/routers/pdf_export.py:33 · png_export.py:31 · render_service/src/index.js · share page.tsx:244
Email snapshot schedules are stored but never sent. SnapshotSchedule rows get next_send_at computed, but there is no SMTP / SES / Resend sender anywhere in the backend. routers/analyst.py:727-767 · shared/models/snapshot_schedules.py
RLS is not enforced on public or scheduled paths. Policies apply only when the owner manually triggers requery-RLS. Anonymous share-link refreshes and cron refreshes run unfiltered SQL. A governance feature that doesn't govern is a security gap. routers/tier5.py:497 (only enforcement point) · public_canvas.py · scheduler.py (no RLS references)
Version history is a dead table. DashboardVersion exists as a model; zero endpoints or code reference it. shared/models/phase2.py:9
Report-view state is ephemeral. Chart-type overrides, forecast/compare toggles, per-chart date filters, layout mode, AI table names vanish on reload. Theme, bookmarks, annotations live in localStorage only — never shared across users or devices. VisuallReport.tsx:581-619
Canvas chat history is lost on every reload — session ID is minted per mount (canvas-{id}-{Date.now()}). Widget locks are in-memory only. CanvasChatPanel.tsx:128 · canvas page.tsx:418-429
Undo/redo covers layout only — not title/type/palette edits or deletions (beyond a 4-second banner), and none at all in the report view. canvas page.tsx:283-352

4Work-area visual enhancement plan

Current state, factually: workspace is #f1f5f9 with a dotted pattern; the page is a fluid white sheet with a 2px dashed border; widgets are white cards with a 3px chart-type colored left border and a permanent 34px gray header bar. Ten concrete fixes:

1 · Kill the dashed border

Dashed = "drop zone placeholder" in every design language. Make the page read like a document: solid white, border-radius: 8px, layered shadow 0 1px 3px rgba(0,0,0,.06), 0 12px 40px rgba(0,0,0,.08). VisuallReport already does exactly this — steal its page treatment.

2 · Fixed-aspect page + letterboxing

A 1280×720 (16:9) page centered with generous letterbox margin instantly reads "professional BI tool". Zoom-to-fit by default; keep the 0.5–1.5× zoom.

3 · Quieter workspace background

Flat #EBEEF3, or dots at ~40% of current contrast. The page should be the only bright thing on screen.

4 · Hover-reveal widget chrome

The permanent 34px gray header × N widgets = visual noise. Headers transparent until hover/selection; title floats in the card's own typography; grip/actions fade in. Selected widget: 2px brand outline + resize handles on all 8 sides (currently only se/e/s).

5 · One card language for edit + view

Adopt VisuallReport's cardBase (softer shadow, 10–12px radius, hover lift) in the editor so both modes feel like one product. Make the colored type-border optional — it fights with data colors.

6 · Theming in the editor

8 report themes don't touch the editor. Persist theme on the dashboard row (a theme column already exists, defaulting to "frost"!) and apply it in both surfaces.

7 · Alignment guides + drop preview

Smart guides while dragging plus a ghost placeholder showing the exact drop cell. react-grid-layout won't provide this — render guide overlays from layout math, or move to a custom drag layer.

8 · Page tabs polish

Bottom strip is the right convention — add per-page icons/colors, overflow scrolling, a compact "+" with a template menu, drag-reorder animation.

9 · Prompt-first empty state

Replace the static 3-step card with a centered command bar ("Describe the page you want…") + 3 template thumbnails. For an agent-native product, the empty state is the chat input.

10 · In-canvas generation skeletons

While the agent generates a chart, show a skeleton card animating in place on the canvas — not just in the chat panel — so the canvas feels alive.

5Prioritized roadmap

P0  Broken / trust

  • Email sender for snapshot schedules
  • RLS enforcement on public + scheduled paths
  • Persist report-view state and canvas chat sessions
  • Full undo/redo command stack (all mutations, agent actions included)

P1  Core BI parity + work-area redesign

  • Fixed 16:9 page + new page/card visuals (§4)
  • Contextual property panel (Format / Data / AI tabs)
  • Text / image widgets
  • Multi-select + alignment tools
  • Number formats + conditional formatting
  • Cross-filtering in the editor
  • Server-side bookmarks & annotations

P2  Agentic differentiators

  • Metric registry UI + verified metrics
  • Agent alerts with natural-language explanations
  • "Explain this point" on every data point
  • Agent-generated page layouts (template candidates)
  • Version diff in prose
  • Relationship editor feeding retrieval accuracy

6The strategic through-line

Power BI's moat is the format pane. Yours is that every capability is reachable through language, and every agent action is inspectable and undoable. Build the property panel so humans can do everything manually — but make the agent the fastest path to the same result, and always show its work (question → SQL → reasoning) in the widget's AI tab.
